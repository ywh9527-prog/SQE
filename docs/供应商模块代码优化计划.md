# 供应商模块代码优化计划

## 📋 项目背景

本次优化的主要目的是将供应商模块的代码优化得更清晰、更专业，避免过于繁杂。

## 🎯 核心原则

### 1. 不影响功能和使用
- 所有优化必须在功能正常的前提下进行
- 用户使用体验不能受到任何负面影响
- 优化后必须经过完整测试验证

### 2. 不允许降级处理
- **严禁**注释掉代码作为"修复"手段
- **严禁**删除功能来"解决"问题
- **严禁**用简陋的方案替代原有的完善方案
- 修复必须是真正的修复，而不是绕过问题

**错误示例**（禁止）：
```css
/* 🔧 修复: 移除基础类的动画，避免动画状态混乱 */
/* animation: fadeIn 0.3s ease-out forwards; */
```

**正确做法**：
- 找到动画状态混乱的根本原因
- 将动画移到正确的位置（如激活状态类）
- 确保动画功能完整保留

### 3. 优化方向

#### A. 代码清晰化
- 统一命名规范
- 移除冗余代码
- 添加必要的注释（说明"为什么"，而非"是什么"）

#### B. 代码专业化
- 遵循单一职责原则
- 遵循开闭原则
- 合理的模块划分

#### C. 修复不良代码习惯
- 消除 `!important` 滥用
- 消除 CSS 和 JS 职责边界模糊
- 消除重复代码
- 消除硬编码
